# 仕組みの説明

ページ上部の余白(マージンボックス)には、通常 `content` プロパティで文字列しか入れられない。表のような構造を持つコンテンツを入れる場合は、CSS 組版の running element を使う。

## running element の流れ

1. 本文中にヘッダー用の要素(この文書では `header.page-header`)を書いておく。
2. CSS で `position: running(pageHeader)` を指定すると、その要素は本文の流れから取り除かれる。
3. `@page` 規則の `@top-center` で `content: element(pageHeader)` と参照すると、各ページの上部余白にその要素が繰り返し描画される。

## 注意点

- ヘッダー表の高さに合わせて `@page` の `margin-top` を広げておく。余白が足りないと表が本文に重なる。
- 表の幅はマージンボックス側では制御しにくいため、表自体に幅を指定する(このサンプルでは A4 幅 210mm から左右余白 18mm ×2 を引いた 174mm)。
- 表紙にヘッダーを出したくない場合は `@page :first` で `content: none` にする。

# ダミー本文

ヘッダーが複数ページにわたって繰り返されることを確認するためのダミー本文。

## 処理概要

受注データの取り込みから出荷指示までの流れを以下に示す。

| 手順 | 処理 | 実行タイミング |
| --- | --- | --- |
| 1 | 受注データ取込 | 毎時 00 分 |
| 2 | 在庫引当 | 取込完了後 |
| 3 | 出荷指示出力 | 引当完了後 |
| 4 | 処理結果通知 | 日次 18:00 |

## 補足事項

- 取込対象は前回実行以降に登録された受注のみとする。
- 引当できなかった受注は保留一覧に登録し、翌営業日に再引当する。
- 出荷指示ファイルは倉庫管理システムの連携フォルダーに出力する。

## エラー処理

取込時にフォーマット不正を検出した場合は該当行をスキップし、エラー一覧に記録する。エラー一覧は処理結果通知メールに添付する。連携フォルダーへの出力に失敗した場合は 5 分間隔で 3 回まで再試行し、それでも失敗した場合は運用担当者へアラートを送信する。
